# Phase 8: Edit dw_decomp C for mods and corrections

**Note:** This phase is not part of the macOS-to-Linux technical port. It is the **user's main goal**: having readable and editable code (Rust + C) that can be modified to make mods, corrections, etc., and run natively on Linux.

Once Phases 1-7 are complete (the game runs on Linux), this phase describes how to use the editable code to change the game.

---

## 1. Where the editable C is

The Digimon World C source lives in the `decomp/` submodule (which is `dw_decomp`):

```
decomp/src/
├── main/          → Main executable, game engine
├── btl/           → Battle
├── evl/           → Events / map events
├── std/           → Standard / field
├── trn/           → Transitions
├── trn2/          → Transitions 2
├── murd/          → "Murder" / game over
├── fish/          → Fishing
├── kar/           → Karaoke / minigames
├── mov/           → Movies
├── vs/            → Versus / multiplayer
├── doo2/          → Minigame
├── dooa/          → Minigame
├── eab/           → Minigame
├── endi/          → Ending
└── shop/          → Shop (included in main in USA version)
```

Each directory contains `.c` and `.h` files you can edit directly.

## 2. Editing and recompilation flow

### Step A: Choose what to change

Examples of simple changes:
- Change Digimon stats (in `src/main/` or `src/btl/`).
- Adjust battle difficulty (in `src/btl/`).
- Fix a behavior bug (any directory).
- Change game text (in `decomp/text/`, converted to C headers).

### Step B: Edit the C

Edit files in `decomp/src/`. These are normal text files, not machine-translated code.

> **Important:** Do not edit generated files in `asm/`, `build/`, `assets/` or `disks/`. Those are generated by `splat` and the build. Only edit `src/` and `text/`.

### Step C: Recompile for Linux

```bash
cd /home/oar/pro/dw1-linux/
./do cargo build --release -p dw1
```

This recompiles the `dw_decomp` C (via `crates/decomp-c/build.rs`) and links the whole executable.

### Step D: Test the change

```bash
export DW1_DISC=/path/to/Digimon\ World\ \(USA\).cue
./target/release/dw1
```

Verify the change has the desired effect and the game still works.

---

## 3. How C connects to the rest

The `dw_decomp` C calls PS1 SDK functions (`GsSortObject4J`, `CdRead`, `SsSeqPlay`, `PadRead`, etc.). These are declared as `extern "C"` and implemented in Rust in `crates/psyq/`.

If your mod needs a new SDK call that does not exist yet in `crates/psyq/`, you must:
1. Add the `extern "C"` declaration in C (or use an existing one).
2. Implement the function in Rust in `crates/psyq/`.
3. Verify against the oracle (PCSX-Redux) that behavior is correct.

---

## 4. Verify against the oracle

After any C change, run the certified replays to make sure nothing broke:

```bash
# Example: new-game replay
export DW1_DISC=/path/to/Digimon\ World\ \(USA\).cue
export DW1_REPLAY=oracle/replays/new-game.txt
export DW1_OUT=/tmp/dw1-test
./target/release/dw1
```

If the canonical state matches the emulator, your change is safe. If it diverges, there is a bug to fix.

---

## 5. Concrete example: change a stat

Suppose you want to change a Digimon's initial HP:

1. Search in `decomp/src/main/` or `decomp/src/btl/` where base stats are defined.
2. Edit the value in the `.c` file.
3. `./do cargo build --release -p dw1`.
4. Run and verify in the game.

---

## 6. Limits of what is editable

| What can be edited | How |
|---|---|
| Game logic (battles, raising, menus) | Edit C in `decomp/src/` |
| Texts and dialogs | Edit YAML in `decomp/text/` (converted to C headers) |
| PS1 SDK behavior | Edit Rust in `crates/psyq/` |
| Graphics / rendering | Edit Rust in `crates/render/` and `crates/backend/` |
| Audio / SPU | Edit Rust in `crates/backend/src/spu.rs` and `crates/psyq/` |
| Saves / memory card | Edit Rust in `crates/dw1/src/saves.rs` |
| Overlays (code loading by parts) | Already handled by dw1-silicon overlay system |
