Digimon World on Apple Silicon

How to build and play dw1-silicon, a native Mac port of Digimon World (PlayStation, 1999, USA release), from your own copy of the game.

What this is

This isn't an emulator. The game's own code, recovered as C by the dw_decomp decompilation project, is compiled for Apple Silicon, and the PlayStation's libraries and hardware underneath it are replaced by a Mac layer written in Rust. The game's rules, randomness, scripts, text, music and saves behave as on the original; it's checked against the original running in an emulator.

Extras like a sharper picture and steadier 3D are options, each labelled original or addition, and the original picture is always one setting away.

Unofficial fan project. Not affiliated with Bandai Namco. The repository holds no game data, and the app you build holds code and text made from the game, so it's for your own Mac: please don't share the app, the disc image or anything made from them.

What you need

  • A Mac with Apple Silicon (M1 or later).
  • Your own disc image of Digimon World (USA), serial SLUS-01032, as a .cue and .bin pair: the usual layout for a dump of your disc (the same one DuckStation plays). The game checks the image when it starts and tells you if it's a different release, compressed or damaged.
  • About 1 GB free for the build, and an internet connection for the first build.
  • The build tools below. The finished app needs nothing but macOS.

Install the build tools

Open Terminal (in Applications › Utilities) and run these. You only need to do this once.

  1. Apple's command line tools (the compiler, Git and Python). A window asks you to install them; if they're already there, it says so.

    xcode-select --install

  2. Rust. Press Enter at the prompt to accept the default install, then close and reopen Terminal.

    curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

The other two tools the build needs, CMake and PyYAML, go inside the project folder in the next section, so there's nothing else to install system-wide (and no Homebrew needed).

Get the code and build

  1. Download the code, with the decompilation it builds on:

    git clone https://github.com/loafykitten/dw1-silicon.git
cd dw1-silicon
git submodule update --init decomp
git -C decomp submodule update --init external/psyq_headers

  2. Give the project its own Python with PyYAML (the build uses it to turn the game's text into code) and CMake (it builds the window and sound library). The build finds both in the .venv folder by itself.

    python3 -m venv .venv
.venv/bin/pip install pyyaml cmake

  3. Build the app and put it in your Applications folder. The first build takes a few minutes; later ones are quick.

    tools/make-app.sh --install

    This makes Digimon World.app in ~/Applications (your home folder's Applications). Without --install it stays in the repo's build folder.

  4. Open Digimon World from Finder or Launchpad.

Prefer the Terminal? PATH="$PWD/.venv/bin:$PATH" cargo run --release -p dw1 runs the game straight from the repo, with its messages in the Terminal.

First start

The first time, the game asks for your disc image. Click the window (or press Enter) and choose the .cue file, or drag the .cue onto the window. It checks the whole image, which takes a second or so, then remembers where it is and starts. The image is only ever read: it isn't copied or changed.

If you move the image later, the game says so and asks again. To choose a different image yourself, start it once like this:

DW1_ASK_DISC=1 ~/Applications/"Digimon World.app"/Contents/MacOS/dw1

If you play in DuckStation with its usual per-game memory cards, the first start also copies the saves from ~/Library/Application Support/DuckStation/memcards/Digimon World (USA)_1.mcd into the game's save slots. It only reads the card, and only that first time. For a card anywhere else (a shared card, another folder), bring its saves in with import-card (Saves).

A keyboard works out of the box, and so does any game controller macOS knows (PlayStation, Xbox, Switch Pro and others). Buttons go by position, so on any controller the bottom face button is Cross.

Picture settings

Change these while you play; a note in the corner says what changed and whether it's the original or an addition. They're kept for next time.

KeySettingDefault
F2Render scale: auto (from the window's size), 1 (the PlayStation's own picture, original), 2, 3, 4, 6 or 8 times sharper additionAuto
F3No wobble: 3D models at their exact positions, so they don't jitter addition; needs a render scale of 2 or moreOn
F4Fit: whole multiples of the picture with black around it original, or as large as the window allows at 4:3 additionWhole multiples
F5Full colour: smooth shading without the PlayStation's 15-bit colour and dither pattern addition; needs a render scale of 2 or moreOn
F6Depth test: 3D polygons hide the ones behind them, so parts of a model that lie behind another stay hidden addition; needs a render scale of 2 or moreOn
F11Fullscreen (or Cmd Ctrl F)Window

For exactly the PlayStation's picture: render scale 1 and whole-multiple fit. The settings live in ~/Library/Application Support/dw1-silicon/settings.txt; delete it for the defaults.

Saves

There are no memory cards to manage: the game has 15 save slots, one per game. New Game, Continue and the in-game saves use them directly; starting a New Game on a used slot asks first.

  • Slots are files in ~/Library/Application Support/dw1-silicon/saves/. Each save that gets replaced is kept in saves/backups/.
  • To play a save in DuckStation, write the slots to a memory card file, then load it there as a card: 
    ~/Applications/"Digimon World.app"/Contents/MacOS/dw1 export-card ~/Desktop/dw1-saves.mcd
  • To bring saves in from a memory card file (they go into free slots; nothing is overwritten): 
    ~/Applications/"Digimon World.app"/Contents/MacOS/dw1 import-card ~/Desktop/some-card.mcd

Close the game before using these two.

When something goes wrong

  • Press F12 the moment something looks wrong. It saves a bug snapshot to ~/Library/Application Support/dw1-silicon/reports/: pictures of the screen, the game's state, the last minute of what you pressed, your settings, copies of your saves and the log. Nothing is sent anywhere.
  • If the game meets something the port doesn't handle yet, it stops rather than guess, and a message says so. Your saves up to the last one are safe.
  • If it ever closes without a message (a crash), the next start tells you and points to that run's log.
  • Logs are in ~/Library/Logs/dw1-silicon/ (the last ten runs).

To report a bug, open an issue on GitHub saying what happened and where, with about.txt, state.txt and log.txt from the snapshot. Please don't attach the disc image or files taken from it.

What's checked so far

Every part of the game is there and runs; parts are "checked" once a recorded playthrough on the original (in an emulator) and the port end in exactly the same game state, step by step.

Checked against the original

  • Starting a new game, File City and Jijimon's house
  • Raising your partner from morning to early afternoon of a day (care menus and the clock; feeding isn't covered yet)
  • Battles, including losing one
  • Training at the gym, the slot bonus and all six kinds
  • The Item Keeper and saving at the save machines
  • Tournaments, whole cups won and lost, and Battle Mode
  • Digivolving, and dying of old age through to the egg and a new partner
  • Fishing, curling, recruiting, and the other gyms
  • The final boss, the ending and the credits
  • Walks through fifteen areas of the island
  • Sound, music and the movies' sound

Running, not yet checked

  • Feeding your partner, and the places and events no recorded playthrough has passed through yet

These run the game's own code too, so they should play as they always did; they're simply where any port bug is most likely to hide.

Known differences

  • Save slots instead of memory cards (they convert both ways, above).
  • Battle Mode's player 2 isn't playable yet: every keyboard and controller drives player 1.
  • The movies' picture can be a shade off the original in places (rounding in the video decoder); their sound matches exactly.
  • No save states, fast forward or widescreen.

Updating

cd dw1-silicon
git pull
git submodule update --init decomp
tools/make-app.sh --install

Your saves, settings and the remembered disc stay where they are.
